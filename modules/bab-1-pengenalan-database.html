Pengenalan Sistem Basis Data

⏱ memuat... Dasar 5 soal quiz

Tujuan Pembelajaran

  • Menjelaskan perbedaan antara data dan informasi dengan contoh nyata
  • Mengidentifikasi komponen-komponen dalam sistem basis data
  • Membandingkan DBMS populer dan kasus penggunaannya
  • Membedakan database relasional dan NoSQL
  • Mendeskripsikan peran MySQL sebagai DBMS utama yang dipelajari

Data vs Informasi — Bukan Hal yang Sama

Bayangkan kamu punya selembar kertas bertuliskan angka: 85, 72, 90, 68, 95. Apa artinya? Tidak ada — itu hanya data mentah. Sekarang, jika kamu tahu angka-angka itu adalah nilai ujian Basis Data kelas XI PPLG 1, urutan dari Andi, Budi, Citra, Dedi, Eka — barulah angka itu menjadi informasi yang bermakna.

AspekDataInformasi
DefinisiFakta mentah yang belum diolahData yang sudah diproses dan bermakna
Contoh85, 72, 90Nilai rata-rata kelas = 82.3
Berguna untukDisimpan, diprosesPengambilan keputusan
SifatObjektif, belum terstrukturKontekstual, terstruktur
💡
Ingat Rumusnya

Data + Konteks + Pemrosesan = Informasi. Database bertugas menyimpan data dengan cara yang memudahkan kita mendapatkan informasi kapan pun dibutuhkan.

Sistem Basis Data

Sistem basis data bukan sekadar "tempat menyimpan data". Ini adalah ekosistem yang terdiri dari lima komponen yang bekerja bersama:

KomponenPeranContoh
DataFakta yang disimpan secara terorganisirNama siswa, nilai, tanggal lahir
HardwarePerangkat keras tempat database berjalanServer, hard disk, RAM
Software (DBMS)Program yang mengelola databaseMySQL, PostgreSQL, Oracle
UserPihak yang berinteraksi dengan databaseAdmin, developer, end-user
ProsedurAturan dan prosedur penggunaan sistemBackup policy, access control

Mengapa Perlu Sistem Basis Data?

Sebelum database ada, data disimpan dalam file-file terpisah. Bayangkan sekolah yang menyimpan data siswa di satu file, nilai di file lain, dan absensi di file ketiga. Masalahnya?

  • Redundansi: nama siswa disimpan berulang di tiga file berbeda
  • Inkonsistensi: update nama di satu file, lupa update di file lain
  • Sulit dicari: butuh buka banyak file untuk menemukan satu informasi
  • Keamanan lemah: siapa saja bisa membuka file tersebut

Database menyelesaikan semua masalah ini sekaligus.

DBMS — Otak di Balik Database

Database Management System (DBMS) adalah perangkat lunak yang menjadi perantara antara user dan data. DBMS bertugas menerima perintah (query), mengeksekusinya terhadap data, lalu mengembalikan hasilnya.

DBMSJenisKelebihanDigunakan oleh
MySQLRelasionalGratis, cepat, komunitas besarWordPress, Facebook (awal)
PostgreSQLRelasionalFitur lengkap, sangat andalInstagram, Reddit
SQLiteRelasionalFile-based, zero configAndroid, aplikasi desktop
Oracle DBRelasionalEnterprise-grade, skalabilitas tinggiBank, perusahaan besar
MongoDBNoSQL (Dokumen)Fleksibel, cocok data tidak terstrukturAplikasi real-time
ℹ️
Mengapa Kita Pakai MySQL?

MySQL gratis (open-source), mudah dipelajari, tersedia di hampir semua hosting web, dan memiliki komunitas terbesar. Ini menjadikannya pilihan ideal untuk belajar dan pengembangan web.

Relasional vs NoSQL — Pilih yang Tepat

Dua paradigma utama dalam dunia database modern adalah Relasional (SQL) dan NoSQL. Keduanya punya kekuatan dan kelemahan masing-masing.

AspekDatabase Relasional (SQL)NoSQL
Struktur dataTabel (baris dan kolom)Dokumen, key-value, graph, kolom
SchemaKaku (harus didefinisikan dulu)Fleksibel (schema-less)
Relasi dataJOIN antar tabel, sangat baikTerbatas atau tidak ada
KonsistensiACID — sangat ketatEventual consistency
Cocok untukAplikasi bisnis, keuangan, sekolahBig data, real-time, media sosial
ContohMySQL, PostgreSQL, OracleMongoDB, Redis, Cassandra

Untuk keperluan PPLG — membangun aplikasi web, sistem informasi sekolah, toko online — database relasional (MySQL) adalah pilihan yang tepat dan sudah lebih dari cukup.

Studi Kasus: Database Perpustakaan Sekolah

Sepanjang e-modul ini, kita akan menggunakan satu studi kasus yang konsisten: Sistem Informasi Perpustakaan SMK. Ini akan menjadi "laboratorium" kita untuk semua perintah SQL dari Bab 1 hingga Bab 7.

Bayangkan perpustakaan sekolah perlu mengelola:

  • Data buku — judul, ISBN, pengarang, genre, stok
  • Data anggota (siswa) — NIS, nama, kelas, status
  • Data peminjaman — siapa meminjam buku apa, kapan, dan sudah dikembalikan belum
SQL — Representasi Awal 
-- Tanpa database: ribuan file terpisah
-- buku_001.txt, buku_002.txt, siswa_andi.txt ...

-- Dengan MySQL: satu query cukup
SELECT anggota.nama_lengkap, buku.judul, peminjaman.tgl_pinjam
FROM peminjaman
JOIN anggota ON peminjaman.id_anggota = anggota.id_anggota
JOIN buku    ON peminjaman.id_buku    = buku.id_buku
WHERE peminjaman.status = 'dipinjam';

Query di atas menampilkan siapa yang sedang meminjam buku apa — dari tiga tabel berbeda — dalam kurang dari satu detik. Inilah kekuatan database relasional.
