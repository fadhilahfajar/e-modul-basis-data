ERD & Perancangan Database

⏱ memuat... Dasar–Menengah 5 soal quiz

Tujuan Pembelajaran

  • Mengidentifikasi entitas, atribut, dan relasi dari studi kasus nyata
  • Menggambar ERD menggunakan notasi Chen dan Crow's Foot
  • Menentukan kardinalitas relasi (1:1, 1:N, M:N)
  • Membedakan Primary Key dan Foreign Key beserta fungsinya
  • Mengkonversi ERD menjadi skema tabel SQL siap pakai

Entitas — Objek yang Punya Data

Sebelum menulis satu baris SQL, seorang database designer selalu bertanya: "Objek apa saja yang perlu kita rekam datanya?". Jawaban pertanyaan itulah yang disebut entitas.

Dalam konteks perpustakaan sekolah kita, entitas utamanya adalah:

  • ANGGOTA — siswa yang terdaftar dan bisa meminjam buku
  • BUKU — koleksi buku yang tersedia di perpustakaan
  • PEMINJAMAN — transaksi peminjaman yang menghubungkan anggota dengan buku
  • PETUGAS — staf perpustakaan yang mengelola sistem

Jenis-jenis Atribut

Setiap entitas memiliki atribut — properti yang mendeskripsikan entitas tersebut. Ada beberapa jenisnya:

Jenis AtributDefinisiContoh (Entitas: ANGGOTA)
SimpleNilai tunggal, tidak bisa dibagi lagiNIS, Kelas
CompositeTersusun dari beberapa atributNama Lengkap (nama depan + belakang)
DerivedNilai diturunkan dari atribut lainUsia (dari Tanggal Lahir)
Multi-valueBisa punya lebih dari satu nilaiNo. Telepon (bisa 2 nomor)
KeyUnik, mengidentifikasi setiap instanceNIS (tidak ada dua siswa ber-NIS sama)

Kardinalitas — Berapa Banyak yang Berelasi?

Relasi antar entitas punya "aturan kuantitas" yang disebut kardinalitas. Ini kritis karena menentukan bagaimana tabel nantinya dirancang.

TipeNotasiArtiContoh
One-to-One (1:1)1 — 1Satu entitas A hanya berelasi dengan satu entitas BSatu petugas memiliki satu akun login
One-to-Many (1:N)1 — NSatu entitas A dapat berelasi dengan banyak entitas BSatu anggota bisa melakukan banyak peminjaman
Many-to-Many (M:N)M — NBanyak entitas A berelasi dengan banyak entitas BSatu anggota bisa pinjam banyak buku; satu buku bisa dipinjam banyak anggota
⚠️
Relasi M:N Harus Dipecah!

Database relasional tidak bisa langsung menyimpan relasi Many-to-Many. Kita harus membuat tabel penghubung (bridge/junction table). Itulah fungsi tabel peminjaman — ia menghubungkan anggota dan buku.

Primary Key vs Foreign Key

Dua jenis kunci ini adalah pondasi dari database relasional — memahaminya dengan benar akan menghindarkan kamu dari error saat mengerjakan JOIN.

AspekPrimary Key (PK)Foreign Key (FK)
FungsiMengidentifikasi baris secara unik dalam tabelnya sendiriMerujuk ke PK di tabel lain untuk membuat relasi
Nilai NULL?❌ Tidak boleh NULL✅ Bisa NULL (jika relasi opsional)
Duplikat?❌ Tidak boleh duplikat✅ Boleh duplikat (banyak peminjaman dari anggota yang sama)
Jumlah per tabelTepat satu PK (bisa composite)Bisa banyak FK
Contohid_anggota di tabel anggotaid_anggota di tabel peminjaman

Konversi ERD ke SQL

Setiap entitas di ERD menjadi satu tabel. Atribut menjadi kolom. Relasi diimplementasikan melalui Foreign Key.

SQL — Implementasi ERD ke Tabel 
-- Entitas ANGGOTA → Tabel anggota
CREATE TABLE anggota (
    id_anggota    INT AUTO_INCREMENT PRIMARY KEY,  -- PK
    nis           VARCHAR(10) NOT NULL UNIQUE,
    nama_lengkap  VARCHAR(100) NOT NULL,
    kelas         VARCHAR(10) NOT NULL,
    status        ENUM('aktif','nonaktif') DEFAULT 'aktif'
);

-- Entitas BUKU → Tabel buku
CREATE TABLE buku (
    id_buku      INT AUTO_INCREMENT PRIMARY KEY,   -- PK
    isbn         VARCHAR(20) NOT NULL UNIQUE,
    judul        VARCHAR(200) NOT NULL,
    stok         INT DEFAULT 0 CHECK (stok >= 0)
);

-- Relasi M:N → Tabel penghubung peminjaman
CREATE TABLE peminjaman (
    id_pinjam  INT AUTO_INCREMENT PRIMARY KEY,
    id_anggota INT NOT NULL,
    id_buku    INT NOT NULL,
    tgl_pinjam DATE DEFAULT (CURRENT_DATE),
    status     ENUM('dipinjam','dikembalikan','terlambat') DEFAULT 'dipinjam',
    -- Foreign Keys mengimplementasikan garis relasi di ERD:
    FOREIGN KEY (id_anggota) REFERENCES anggota(id_anggota),
    FOREIGN KEY (id_buku)    REFERENCES buku(id_buku)
);
💡
Urutan CREATE TABLE Penting!

Tabel yang mengandung Foreign Key harus dibuat setelah tabel yang dirujuknya. Buat anggota dan buku dulu, baru peminjaman.

Langkah Merancang Database dari Studi Kasus

Ini adalah alur yang digunakan profesional saat merancang database dari kebutuhan bisnis:

  1. Baca dan pahami kebutuhan — identifikasi siapa penggunanya dan apa yang perlu dilakukan sistem
  2. Identifikasi entitas — kata benda penting dalam kebutuhan = calon entitas
  3. Tentukan atribut — data apa yang perlu disimpan untuk setiap entitas
  4. Identifikasi relasi — bagaimana entitas-entitas saling berhubungan
  5. Tentukan kardinalitas — 1:1, 1:N, atau M:N untuk setiap relasi
  6. Gambar ERD — visualisasikan menggunakan notasi yang dipilih
  7. Validasi — periksa apakah semua kebutuhan tercakup
  8. Konversi ke SQL — buat CREATE TABLE berdasarkan ERD
