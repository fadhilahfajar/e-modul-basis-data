DDL — Mendefinisikan Struktur Database

⏱ memuat... Dasar–Menengah 5 soal quiz

Tujuan Pembelajaran

  • Membuat database dan tabel menggunakan perintah CREATE
  • Memilih tipe data MySQL yang tepat untuk setiap kolom
  • Menerapkan constraint (PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK)
  • Memodifikasi struktur tabel dengan ALTER TABLE
  • Membedakan DROP TABLE dan TRUNCATE TABLE beserta risikonya

DDL — Mendefinisikan Sebelum Mengisi

Data Definition Language (DDL) adalah subset perintah SQL yang digunakan untuk mendefinisikan, memodifikasi, dan menghapus struktur database — bukan isinya. Analogi terbaik: DDL adalah arsitek yang merancang gedung, sementara DML (Bab 4) adalah orang yang mengisi gedung itu dengan furnitur.

Perintah DDLFungsi
CREATEMembuat objek baru (database, tabel, view, index)
ALTERMengubah struktur objek yang sudah ada
DROPMenghapus objek beserta seluruh isinya (permanen!)
TRUNCATEMenghapus semua baris tabel, tapi struktur tetap ada

CREATE DATABASE & CREATE TABLE

SQL — Membuat Database & Tabel 
-- 1. Buat database (IF NOT EXISTS = aman, tidak error jika sudah ada)
CREATE DATABASE IF NOT EXISTS perpustakaan_smk;

-- 2. Pilih database yang akan digunakan
USE perpustakaan_smk;

-- 3. Buat tabel anggota
CREATE TABLE anggota (
    id_anggota    INT AUTO_INCREMENT PRIMARY KEY,
    nis           VARCHAR(10)  NOT NULL UNIQUE,
    nama_lengkap  VARCHAR(100) NOT NULL,
    kelas         VARCHAR(10)  NOT NULL,
    email         VARCHAR(100),
    tanggal_daftar DATE DEFAULT (CURRENT_DATE),
    status        ENUM('aktif', 'nonaktif') DEFAULT 'aktif'
);

-- 4. Buat tabel buku
CREATE TABLE buku (
    id_buku      INT AUTO_INCREMENT PRIMARY KEY,
    isbn         VARCHAR(20)  NOT NULL UNIQUE,
    judul        VARCHAR(200) NOT NULL,
    pengarang    VARCHAR(100) NOT NULL,
    genre        VARCHAR(50),
    stok         INT DEFAULT 1 CHECK (stok >= 0),
    tahun_terbit YEAR
);

-- 5. Buat tabel peminjaman (harus dibuat SETELAH anggota & buku)
CREATE TABLE peminjaman (
    id_pinjam   INT AUTO_INCREMENT PRIMARY KEY,
    id_anggota  INT NOT NULL,
    id_buku     INT NOT NULL,
    tgl_pinjam  DATE NOT NULL DEFAULT (CURRENT_DATE),
    tgl_kembali DATE,
    status      ENUM('dipinjam','dikembalikan','terlambat') DEFAULT 'dipinjam',
    FOREIGN KEY (id_anggota) REFERENCES anggota(id_anggota) ON DELETE RESTRICT,
    FOREIGN KEY (id_buku)    REFERENCES buku(id_buku) ON DELETE RESTRICT
);

💡
Aturan Emas Memilih Tipe Data

Pilih tipe yang paling kecil yang cukup menampung data. TINYINT untuk angka 0-100, bukan INT. VARCHAR(100) untuk nama, bukan TEXT. Ini menghemat storage dan mempercepat query.

Constraint — Penjaga Integritas Data

ConstraintFungsiContoh
PRIMARY KEYIdentifikasi unik setiap baris. Tidak bisa NULL, tidak bisa duplikat.id_anggota INT PRIMARY KEY
FOREIGN KEYMemastikan nilai merujuk ke PK yang valid di tabel lain.FOREIGN KEY (id_buku) REFERENCES buku(id_buku)

CHECKValidasi nilai berdasarkan kondisi yang ditentukan.stok INT CHECK (stok >= 0)

ALTER TABLE — Modifikasi Struktur

Database jarang dirancang sempurna dari awal. ALTER TABLE digunakan untuk mengubah struktur tabel yang sudah ada tanpa menghapus datanya.

SQL — ALTER TABLE 
-- Tambah kolom baru
ALTER TABLE anggota
ADD COLUMN no_hp VARCHAR(15) AFTER email;

-- Ubah tipe data atau constraint kolom
ALTER TABLE anggota
MODIFY COLUMN nama_lengkap VARCHAR(150) NOT NULL;

-- Ganti nama kolom (MySQL 8.0+)
ALTER TABLE buku
RENAME COLUMN tahun_terbit TO tahun_publikasi;

-- Hapus kolom (data di kolom itu ikut hilang!)
ALTER TABLE anggota
DROP COLUMN no_hp;

-- Tambah constraint baru
ALTER TABLE peminjaman
ADD CONSTRAINT chk_tgl CHECK (tgl_kembali >= tgl_pinjam OR tgl_kembali IS NULL);

DROP vs TRUNCATE — Perbedaan Kritis

🚨
Perintah Berbahaya — Tidak Bisa Dibatalkan!

DROP dan TRUNCATE adalah perintah yang tidak bisa di-undo dengan ROLLBACK biasa. Selalu backup dulu sebelum menggunakan perintah ini di data produksi.

AspekDROP TABLETRUNCATE TABLEDELETE (tanpa WHERE)
Menghapus struktur?✅ Ya — tabel hilang❌ Tidak — struktur tetap❌ Tidak
Menghapus data?✅ Ya — semua data✅ Ya — semua baris✅ Ya — semua baris
Auto-increment reset?Ya (tabel hilang)✅ Ya — mulai dari 1 lagi❌ Tidak
Bisa di-rollback?❌ Tidak❌ Tidak✅ Ya (dalam transaksi)
KecepatanSangat cepatSangat cepatLambat (log per baris)
SQL — DROP dan TRUNCATE 
-- Hapus tabel beserta strukturnya (irreversible!)
DROP TABLE IF EXISTS peminjaman;
-- Catatan: hapus tabel yang punya FK dulu sebelum tabel yang dirujuk

-- Hapus semua data, tapi struktur tetap ada
TRUNCATE TABLE peminjaman;
-- AUTO_INCREMENT kembali ke 1

-- Hapus database seluruhnya (SANGAT BERBAHAYA)
DROP DATABASE IF EXISTS perpustakaan_smk;
