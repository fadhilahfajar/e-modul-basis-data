Normalisasi Database

⏱ memuat... Menengah 5 soal quiz

Tujuan Pembelajaran

  • Mengidentifikasi anomali INSERT, UPDATE, dan DELETE pada tabel tidak normal
  • Memahami konsep Ketergantungan Fungsional (Functional Dependency)
  • Menerapkan 1NF: menghilangkan atribut tidak atomik dan repeating group
  • Menerapkan 2NF: menghilangkan partial dependency
  • Menerapkan 3NF: menghilangkan transitive dependency

Masalah Tanpa Normalisasi

Bayangkan kita menyimpan data peminjaman buku dalam satu tabel besar — terasa praktis, tapi menyimpan bom waktu. Tiga jenis anomali menunggu:

Jenis AnomaliSkenarioDampak
Anomali INSERTIngin menambah buku baru yang belum pernah dipinjamTidak bisa — kolom id_anggota wajib diisi (NOT NULL)
Anomali UPDATEPengarang buku "A" berganti namaHarus update ratusan baris yang meminjam buku yang sama — rawan inkonsistensi
Anomali DELETEHapus catatan peminjaman terakhir sebuah bukuData buku ikut terhapus secara tidak sengaja

Ketergantungan Fungsional

Sebelum normalisasi, kita perlu memahami Ketergantungan Fungsional (Functional Dependency) — konsep inti yang menentukan apakah sebuah tabel perlu dipecah.

Notasi: A → B artinya "nilai A secara unik menentukan nilai B". Jika kita tahu nilai A, kita tahu persis nilai B-nya.

Contoh Functional Dependency 
-- id_anggota → nama_lengkap, kelas  (PK menentukan semua atribut lain di tabelnya)
-- isbn → judul, pengarang, genre    (ISBN unik, menentukan info buku)
-- id_pinjam → tgl_pinjam, status   (setiap peminjaman punya tanggal & status sendiri)

-- Transitive (berbahaya, dilanggar di 3NF):
-- id_pinjam → id_buku → judul       (judul bergantung pada id_buku, bukan langsung ke PK)

Studi Kasus Normalisasi — 0NF sampai 3NF

Kita mulai dari tabel paling "naif" — semua data dalam satu tabel — lalu normalisasi bertahap.

↓Terapkan 3NF: hilangkan transitive dependency — atribut non-key tidak boleh bergantung pada atribut non-key lain
3NF — Bentuk Normal Ketiga ✓

Jika ada kolom seperti kode_jurusan → nama_jurusan, pisahkan ke tabel jurusan.

SQL — Implementasi 3NF Final 
-- Tabel jurusan (pisahkan dari anggota jika ada transitive dependency)
CREATE TABLE jurusan (
    kode_jurusan CHAR(5) PRIMARY KEY,   -- 'PPLG'
    nama_jurusan VARCHAR(100) NOT NULL  -- 'Pengembangan Perangkat Lunak & Gim'
);

-- Tabel anggota — sekarang benar-benar 3NF
CREATE TABLE anggota (
    id_anggota   INT AUTO_INCREMENT PRIMARY KEY,
    nis          VARCHAR(10) UNIQUE NOT NULL,
    nama_lengkap VARCHAR(100) NOT NULL,
    kode_jurusan CHAR(5),
    tingkat      TINYINT,  -- 10, 11, 12
    FOREIGN KEY (kode_jurusan) REFERENCES jurusan(kode_jurusan)
);
-- nama_jurusan tidak ada di sini — ambil via JOIN jika diperlukan
💡
Aturan Cepat Cek 3NF

Tanyakan setiap kolom non-key: "Apakah kolom ini bergantung langsung ke Primary Key, atau ke kolom non-key lain?" Jika ke kolom non-key lain → ada transitive dependency → perlu dipecah.

Ringkasan — 3 Bentuk Normal

Bentuk NormalSyaratYang Dihilangkan
1NFSetiap sel atomik, ada PK, tidak ada repeating groupMulti-value attribute, kolom duplikat
2NFMemenuhi 1NF + tidak ada partial dependencyAtribut yang hanya bergantung sebagian PK (pada composite PK)
3NFMemenuhi 2NF + tidak ada transitive dependencyAtribut non-key yang bergantung pada atribut non-key lain
