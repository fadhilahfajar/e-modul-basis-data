Objek Database Lanjutan

Tujuan Pembelajaran

  • Membuat dan menggunakan VIEW untuk menyederhanakan query kompleks

VIEW — Tabel Virtual yang Menyederhanakan Segalanya

VIEW adalah query SELECT yang disimpan dengan nama tertentu di database. Setelah dibuat, kita bisa menggunakannya seperti tabel biasa — padahal di balik layar, MySQL menjalankan query aslinya secara otomatis.

Manfaat VIEWContoh Kasus
Menyederhanakan queryQuery JOIN 3 tabel yang dipakai berkali-kali → buat jadi satu VIEW
Keamanan dataTampilkan hanya kolom tertentu ke user — sembunyikan kolom sensitif (password, gaji)
KonsistensiLogika bisnis terpusat di satu tempat — tidak perlu ditulis ulang di setiap query
SQL — CREATE VIEW 
-- Buat VIEW laporan peminjaman aktif
CREATE OR REPLACE VIEW v_peminjaman_aktif AS
SELECT
    p.id_pinjam,
    a.nama_lengkap                            AS peminjam,
    a.kelas,
    b.judul                                   AS judul_buku,
    b.genre,
    p.tgl_pinjam,
    DATEDIFF(CURRENT_DATE, p.tgl_pinjam)      AS hari_pinjam,
    CASE
        WHEN DATEDIFF(CURRENT_DATE, p.tgl_pinjam) > 7 THEN 'TERLAMBAT'
        ELSE 'Tepat Waktu'
    END AS keterlambatan
FROM peminjaman p
JOIN anggota a ON p.id_anggota = a.id_anggota
JOIN buku    b ON p.id_buku    = b.id_buku
WHERE p.status = 'dipinjam';

-- Gunakan VIEW seperti tabel biasa
SELECT * FROM v_peminjaman_aktif WHERE keterlambatan = 'TERLAMBAT';
SELECT peminjam, COUNT(*) AS total FROM v_peminjaman_aktif GROUP BY peminjam;

-- Hapus VIEW
DROP VIEW IF EXISTS v_peminjaman_aktif;

Stored Procedure — Logika Bisnis di Dalam Database

Stored Procedure adalah blok kode SQL yang tersimpan di database dan bisa dipanggil berulang kali. Seperti fungsi/method di bahasa pemrograman, tapi berjalan di sisi database.

SQL — Stored Procedure 
-- WAJIB ganti delimiter sebelum membuat procedure
DELIMITER //

CREATE PROCEDURE proc_pinjam_buku(
    IN  p_id_anggota INT,
    IN  p_id_buku    INT,
    OUT p_pesan      VARCHAR(100)
)
BEGIN
    DECLARE v_stok INT;
    DECLARE v_status VARCHAR(20);

    -- Cek stok buku
    SELECT stok INTO v_stok FROM buku WHERE id_buku = p_id_buku;

    -- Cek status anggota
    SELECT status INTO v_status FROM anggota WHERE id_anggota = p_id_anggota;

    IF v_stok IS NULL THEN
        SET p_pesan = 'ERROR: Buku tidak ditemukan';
    ELSEIF v_stok <= 0 THEN
        SET p_pesan = 'ERROR: Stok buku habis';
    ELSEIF v_status != 'aktif' THEN
        SET p_pesan = 'ERROR: Anggota tidak aktif';
    ELSE
        -- Catat peminjaman
        INSERT INTO peminjaman (id_anggota, id_buku, tgl_pinjam, status)
        VALUES (p_id_anggota, p_id_buku, CURRENT_DATE, 'dipinjam');

        -- Kurangi stok
        UPDATE buku SET stok = stok - 1 WHERE id_buku = p_id_buku;

        SET p_pesan = 'SUKSES: Peminjaman berhasil dicatat';
    END IF;
END//

DELIMITER ;

-- Memanggil procedure
CALL proc_pinjam_buku(1, 3, @hasil);
SELECT @hasil;  -- tampilkan output parameter
💡
Kenapa Perlu DELIMITER?

MySQL menggunakan titik koma (;) sebagai penanda akhir perintah. Di dalam procedure, kita juga pakai titik koma untuk setiap statement — ini akan membingungkan parser. Solusinya: ganti delimiter sementara jadi //, tulis procedure, lalu kembalikan ke ;.

TRIGGER — Otomasi yang Berjalan Sendiri

Trigger adalah kode yang otomatis dieksekusi ketika terjadi operasi INSERT, UPDATE, atau DELETE pada tabel tertentu. Tidak perlu dipanggil manual — database menjalankannya sendiri.

TimingEventKasus Penggunaan
BEFORE INSERTINSERTValidasi data sebelum masuk ke tabel
AFTER INSERTINSERTUpdate tabel lain setelah data baru masuk
BEFORE UPDATEUPDATECek aturan bisnis sebelum data diubah
AFTER UPDATEUPDATECatat ke log, update summary table
BEFORE DELETEDELETECegah penghapusan data penting
AFTER DELETEDELETEBersihkan data terkait di tabel lain
SQL — TRIGGER 
DELIMITER //

-- AFTER INSERT: kurangi stok saat peminjaman baru dibuat
CREATE TRIGGER trg_kurangi_stok
AFTER INSERT ON peminjaman
FOR EACH ROW
BEGIN
    UPDATE buku SET stok = stok - 1
    WHERE id_buku = NEW.id_buku;
    -- NEW = baris yang baru saja diinsert
END//

-- AFTER UPDATE: tambah stok saat buku dikembalikan
CREATE TRIGGER trg_kembalikan_stok
AFTER UPDATE ON peminjaman
FOR EACH ROW
BEGIN
    IF NEW.status = 'dikembalikan' AND OLD.status = 'dipinjam' THEN
        UPDATE buku SET stok = stok + 1
        WHERE id_buku = NEW.id_buku;
        -- OLD = nilai sebelum diupdate, NEW = nilai setelah diupdate
    END IF;
END//

DELIMITER ;
⚠️
Gunakan Trigger dengan Bijak

Trigger berjalan otomatis dan tidak terlihat di query — ini bisa menyulitkan debugging jika terlalu banyak trigger. Gunakan hanya untuk logika yang memang harus selalu berjalan, seperti audit log atau update stok.

Transaksi & Sifat ACID

Bayangkan proses peminjaman buku: kita harus INSERT ke tabel peminjaman DAN UPDATE stok buku. Jika koneksi putus di tengah jalan, kita bisa punya catatan peminjaman tanpa stok berkurang — data inkonsisten. Transaksi mencegah ini terjadi.

Sifat ACIDArtiJaminan
AtomicitySemua atau tidak sama sekaliINSERT + UPDATE keduanya berhasil, atau keduanya dibatalkan
ConsistencyData selalu validConstraint dan aturan bisnis terpenuhi setelah transaksi
IsolationTransaksi tidak saling menggangguDua transaksi bersamaan tidak merusak satu sama lain
DurabilityPerubahan yang COMMIT bersifat permanenData tidak hilang meskipun server crash setelah COMMIT
SQL — Transaksi 
START TRANSACTION;

    -- Langkah 1: catat peminjaman
    INSERT INTO peminjaman (id_anggota, id_buku, tgl_pinjam, status)
    VALUES (1, 3, CURRENT_DATE, 'dipinjam');

    -- Langkah 2: kurangi stok
    UPDATE buku SET stok = stok - 1 WHERE id_buku = 3;

    -- Cek apakah stok menjadi negatif
    -- Jika ada masalah: ROLLBACK; (batalkan semua)
    -- Jika semua baik: COMMIT; (simpan permanen)

COMMIT;

-- Contoh dengan ROLLBACK:
START TRANSACTION;
    UPDATE buku SET stok = stok - 1 WHERE id_buku = 5;
    -- Ternyata stok sudah 0 sebelumnya! Batalkan:
ROLLBACK;  -- stok kembali seperti semula

-- SAVEPOINT: titik simpan di tengah transaksi
START TRANSACTION;
    INSERT INTO log_aktivitas (aksi) VALUES ('mulai proses');
    SAVEPOINT sp1;

    UPDATE buku SET stok = stok - 1 WHERE id_buku = 2;
    -- Jika update ini bermasalah:
    ROLLBACK TO sp1;  -- kembali ke SAVEPOINT, INSERT log tetap ada

COMMIT;

INDEX — Mempercepat Pencarian Data

INDEX bekerja seperti indeks buku — tanpanya, MySQL harus membaca setiap baris untuk menemukan data (full table scan). Dengan index, pencarian bisa ribuan kali lebih cepat pada tabel besar.

SQL — INDEX 
-- Buat index pada kolom yang sering digunakan di WHERE atau JOIN
CREATE INDEX idx_buku_genre ON buku(genre);
CREATE INDEX idx_pinjam_status ON peminjaman(status, tgl_pinjam);

-- Lihat index yang ada di sebuah tabel
SHOW INDEX FROM peminjaman;

-- Hapus index (PK dan UNIQUE sudah otomatis punya index)
DROP INDEX idx_buku_genre ON buku;

-- Kapan PERLU index? → Kolom yang sering di WHERE, JOIN ON, ORDER BY
-- Kapan TIDAK perlu? → Tabel kecil, kolom dengan sedikit nilai unik (ENUM status)
